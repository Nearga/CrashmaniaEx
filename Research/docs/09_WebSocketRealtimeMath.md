# WebSocket Real-Time Protocol & Provably Fair Math

## Executive Summary
A crash game's entire state machine and calculation loops are hosted **completely server-side** to eliminate client-side memory-hacking and ensure absolute security. The Unity WebGL build simply acts as a high-fidelity visual player that receives real-time broadcasts and renders the rocket’s height, animations, sound effects, and UI counters accordingly.

This document serves as the architecture blueprint for building the WebSocket Server and the Provably Fair mathematical engine required to host your custom Crash game.

---

## 1. WebSocket Connection Setup
When Unity initializes, it establishes a persistent WebSocket connection to the server. The connection URL structure contains crucial sweepstakes and authentication parameters:

```text
wss://crash.crashmania.com/ws?token={token}&gameType={gameType}&clientSeed={clientSeed}&gameSetId={gameSetId}&flow_id={flow_id}
```

* **`token`**: The player's Web SSO `access_token` (JWT or session token) to authenticate the connection.
* **`gameType`**: `1` for Real Sweepstakes Coins (SweepCoins / cash mode), `0` for Virtual Free Coins (Coins / fun mode).
* **`clientSeed`**: A client-side seed string generated by active players to input into the Provably Fair RNG.
* **`gameSetId`**: Categorizes the active game pool index.

## 2. Server-Side Game Loop State Machine
The server operates a continuous, infinite game loop consisting of 4 distinct phases:

```mermaid
state-diagram
    [*] --> Countdown
    Countdown --> Flying : Timer Ends (0.0s)
    Flying --> Crashed : Multiplier reaches Crash Point
    Crashed --> Intermission : Fills History & Leaderboards
    Intermission --> Countdown : Delay Ends (e.g., 5.0s)
```

### A. Phase 1: Countdown (Lobby Preparation)
* **Duration:** Usually 5.0 to 8.0 seconds.
* **Server Action:** Accepts bets from clients via WebSocket. Calculates the final crash multiplier for the upcoming round.
* **Broadcast to Client:** Dispatches `GAME_COUNTDOWN` every second with the remaining time.

---

### B. Phase 2: Flying (Active Round)
* **Duration:** Dynamic (dependent on the calculated crash multiplier).
* **Server Action:** Increments the multiplier in real time using a standard curve function:
  $$f(t) = 1.006^{100 \cdot t}$$
  *(where $t$ is the elapsed seconds since rocket launch).*
* **Broadcast to Client:** Emits `GAME_MULTIPLIER_UPDATE` every 50ms–100ms containing the current climbing multiplier value.
* **Player Action:** Players can click **Cash Out** during this phase. If successful, the server registers the win and emits `CASH_OUT_RESULT`.

---

### C. Phase 3: Crashed (Round Explosion)
* **Duration:** 2.0 to 3.0 seconds (for showing the explosion animation).
* **Server Action:** Rejects any further cash-outs. Deducts losses, credits wins to database balances.
* **Broadcast to Client:** Emits `GAME_END` declaring the exact crash point and cryptographic seeds.

---

### D. Phase 4: Intermission (Clean Up)
* **Duration:** 1.0 to 2.0 seconds.
* **Server Action:** Refreshes internal lists, updates global leaderboards, and resets the lobby state.
* **Broadcast to Client:** Emits `PLAYER_BETS_UPDATE` (empty list) to clear the client sidebar.

## 4. Provably Fair Math Engine (C# / Node.js)
To prove to players that outcomes are not manipulated in real time based on active bets, crash multipliers are pre-calculated using a **hashed chain of seeds**. 

### Cryptographic Algorithm
1. **Combine Seeds:** Combine the secret Server Seed (pre-published as a SHA-256 hash before the round) with the public Client Seed (contributed by the first active player of the round) and a Nonce (round number).
2. **Generate Hash:** Compute the HMAC-SHA256:
   $$Hash = HMAC\_SHA256(ServerSeed, ClientSeed + Nonce)$$
3. **Parse Bytes:** Extract the first 52 bits (13 hex characters) of the generated hash and convert it to a decimal integer ($X$).
4. **Instant Crash (House Edge):** Standard crash games enforce a **3% instant crash rate** (the rocket crashes instantly at `1.00x` to secure the house edge). If $X \pmod{100} < 3$, the multiplier is set to `1.00`.
5. **Calculate Multiplier:** If it survives the instant crash check, calculate the ascending scale:
   $$Multiplier = \frac{97}{1.00 - \frac{X}{2^{52}}}$$
   *(The result is rounded down to two decimal places, e.g. `2.45x`).*

---

### Node.js Server Implementation (RNG Engine)
Below is the clean backend Node.js code to run the Provably Fair calculations on your server:

```javascript
const crypto = require('crypto');

/**
 * Calculates the crash multiplier for a round.
 * @param {string} serverSeed - Hexadecimal secret server seed
 * @param {string} clientSeed - Hexadecimal/string public client seed
 * @param {number} nonce - The active round number
 * @returns {number} The final crash multiplier (e.g. 2.45)
 */
function calculateCrashPoint(serverSeed, clientSeed, nonce) {
  // 1. Combine client seed with nonce
  const salt = `${clientSeed}-${nonce}`;
  
  // 2. Generate HMAC-SHA256 hash
  const hmac = crypto.createHmac('sha256', serverSeed);
  hmac.update(salt);
  const hash = hmac.digest('hex');
  
  // 3. Convert first 13 hex characters (52 bits) to decimal integer
  const hexPart = hash.substring(0, 13);
  const X = parseInt(hexPart, 16);
  
  // 4. Test for 3% House Edge Instant Crash (1.00x)
  if (X % 100 < 3) {
    return 1.00;
  }
  
  // 5. Calculate multiplier scale
  const e = Math.pow(2, 52);
  const multiplier = (97 * e) / (e - X);
  
  // Round down to two decimal places
  return Math.floor(multiplier) / 100;
}

// Example usage:
const serverSeed = "e3b0c44298fc1c149afbf4c8996fb92427ae41e4649b934ca495991b7852b855";
const clientSeed = "provably_fair_client_seed";
const round = 105;

const crashPoint = calculateCrashPoint(serverSeed, clientSeed, round);
console.log(`Round ${round} Crash Point: ${crashPoint}x`);
// Output: e.g. "Round 105 Crash Point: 2.14x"
```
